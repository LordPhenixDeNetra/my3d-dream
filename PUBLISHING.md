# Publishing a release

Release runbook. Everything happens through a tag: `.github/workflows/release.yml` publishes to npm
and creates the GitHub release.

## One-time prerequisites

1. npm account with **2FA** enabled.
2. npm token of the **Automation** type, or a **granular** token with *Read and write* on all packages
   and **Bypass two-factor authentication** checked. Tokens that still require an OTP fail in CI with
   `EOTP`.
3. GitHub secret **`NPM_TOKEN`**: *Settings* → *Secrets and variables* → *Actions*.
4. **Public** repository: without it, npm provenance is refused.

## Before tagging

- [ ] `main` branch up to date, working tree clean (`git status` empty);
- [ ] `npm test` green locally;
- [ ] `package.json`: `version` bumped according to semver;
- [ ] `CHANGELOG.md`: `Unreleased` section turned into a dated version;
- [ ] `README.md`: every quoted measurement comes from a file regenerated by the tests;
- [ ] `LICENSE` present, year up to date;
- [ ] no trace of `upstream/`: `git ls-files | Select-String upstream` returns nothing.

## Procedure

```powershell
npm test
npm version patch          # or minor / major — creates the commit and the vX.Y.Z tag
git push --follow-tags
```

`npm version` writes its own commit message. To add the co-author:

```powershell
git commit --amend -m "chore: release vX.Y.Z" -m "Co-authored-by: NetraDevLPDN <144937204+NetraDevLPDN@users.noreply.github.com>"
git tag -f vX.Y.Z
git push --force-with-lease --follow-tags
```

## What the workflow does

1. checks that the tag (`vX.Y.Z`) matches `version` in `package.json` — immediate failure otherwise;
2. checks that `NPM_TOKEN` is present, with an explicit message if it is empty;
3. `npm install`;
4. skips publication if the version already exists on npm, then runs
   `npm publish --provenance --access public`, preceded by `prepublishOnly` which runs `npm test`:
   a red suite blocks publication;
5. creates the GitHub release with generated notes, as a *prerelease* if the tag contains a hyphen.

## Verify

- `https://www.npmjs.com/package/my3d-dream` — version and *Provenance* tab pointing at the commit;
- `https://github.com/LordPhenixDeNetra/my3d-dream/releases` — release and notes;
- `npm i -g my3d-dream@X.Y.Z && my3d stats`.

## Manual publication (fallback)

The workflow is the normal path. If CI is unavailable:

```powershell
$env:MY3D_SKIP_BROWSER="1"
npm login
npm publish --access public --otp=123456
```

Without `--provenance`: the signature can only be produced by a GitHub runner.

## When something goes wrong

| Symptom | Cause | Action |
|---|---|---|
| `tag v… does not match` | tag and `version` diverge | fix `version`, redo the tag |
| `ENEEDAUTH` | no token reached npm | check that the secret is a repository secret named exactly `NPM_TOKEN` |
| `EOTP` | token requiring an OTP | regenerate it with *Bypass 2FA* checked |
| `E401` | invalid or revoked token | regenerate and update the secret |
| `E403` | token without publish rights | choose *Read and write (publish and stage)* |
| `provenance` refused | private repository or missing `id-token` | check `permissions: id-token: write` |
| red tests inside `npm publish` | `prepublishOnly` | fix, then create a **new** tag |

## Rolling back

- **Within 72 hours**: `npm unpublish my3d-dream@X.Y.Z` (npm policy: the version cannot be reused, and
  removal beyond 72 hours is exceptional).
- **Beyond that**: `npm deprecate my3d-dream@X.Y.Z "reason"`, then publish a fix. A published version
  is never rewritten.
- **Git tag**: delete the remote tag (`git push --delete origin vX.Y.Z`) and the GitHub release, then
  publish under a higher number.

## Prereleases

```powershell
npm version prerelease --preid=rc   # 0.2.0-rc.0
git push --follow-tags
```

The workflow marks the GitHub release as a *prerelease* automatically. The npm `latest` tag is not
moved by a prerelease.
